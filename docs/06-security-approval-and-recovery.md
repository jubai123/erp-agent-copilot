# 安全、审批与故障恢复

## 1. 安全目标

- 未授权用户不能查看跨租户数据或执行Tool。
- 知识库、用户输入和Tool输出不能覆盖系统安全策略。
- 高风险操作必须经过明确审批。
- 外部请求不能访问未授权网络目标。
- Worker重启、消息重投和网络重试不能造成重复写操作。
- 密钥、Token和个人敏感信息不能进入日志、Prompt和评测数据。

## 2. 资产与攻击面

主要资产：

- 用户身份、租户和权限。
- Tool凭据和外部系统访问能力。
- ERP业务规则、商品、供应商、订单和库存信息。
- Run、审批、审计和安全事件。
- Artifact及其中可能包含的敏感内容。

主要攻击面：用户输入、知识文档、OpenAPI导入、LLM输出、Tool参数、Tool URL、Tool响应、审批接口、SSE和Artifact下载。

## 3. 五层防护

### 输入层

- 校验身份、租户、内容类型和长度。
- 限制请求频率和单Run预算。
- 用户不能提交内部字段，如`approved=true`或任意Scope。

### 知识层

- 外部文档默认不可信。
- 文档内容与系统指令使用明确边界隔离。
- 检测Prompt Injection、秘密模式和跨租户标识。
- 可疑文档进入隔离状态，不参与召回。

### 计划层

- 只允许注册的Tool和合法版本。
- 检查依赖、风险、Scope、参数来源和审批要求。
- Planner不能降低Tool固有风险级别。

### 执行层

- URL allowlist、DNS和IP校验、重定向限制。
- 参数JSON Schema校验、超时和响应大小限制。
- 写操作要求审批令牌和幂等键。
- 可选Sandbox限制网络、文件系统、CPU、内存和时间。

### 输出层

- Secret和PII Redaction。
- 引用验证和敏感Artifact访问控制。
- 安全事件和关键写操作进入不可变审计日志。

## 4. RBAC与Tool Scope

权限以租户为边界，角色只聚合Scope，不在代码中硬编码业务特例。

示例Scope：

```text
knowledge:erp:read
product:read
supplier:read
order:read
order:create
order:update
order:cancel
approval:order
admin:tool
admin:apikey
```

凭证是敏感度最高的资源——签发/吊销 API key 等于授予/收回"以某用户身份认证"的能力，故与工具目录管理（`admin:tool`）分开，单独用 `admin:apikey` 保护（`POST /v1/api-keys`、`GET /v1/api-keys`、`DELETE /v1/api-keys/{key_id}`）。

授权检查同时考虑：用户Scope、Tool所需Scope、资源租户、环境和审批状态。

## 5. 审批模型

审批请求保存：

- Run和Step。
- Tool版本和参数摘要。
- 目标资源、环境和影响范围。
- 风险等级、证据和建议动作。
- 请求人、审批人和租户。
- 过期时间和审批状态。
- 参数哈希和Plan版本。

审批只对指定Plan版本和参数哈希有效。Plan或参数发生变化后必须重新审批。

状态建议：

```text
PENDING → APPROVED
        → REJECTED
        → EXPIRED
        → CANCELLED
```

## 6. SSRF与出口控制

请求发出前：

1. 只允许`https`或明确批准的本地模拟器协议。
2. 根据Tool版本选择预注册Host，不接受Planner提交Host。
3. DNS解析后拒绝回环、链路本地、组播、保留地址和未授权私网地址。
4. 禁止自动跟随到不同Host的重定向。
5. 每次重定向重新执行地址检查。
6. 限制端口、响应大小、连接时间和总时间。

### ERP 模拟器入站令牌门

ERP 模拟器（受信内部 Host，独立 FastAPI 进程）被直接暴露于网络时用共享密钥保护入站：

- 配置 `SIMULATOR_SHARED_SECRET` 后，除 `/health` 外所有模拟器路由 **fail-closed**：`X-Simulator-Token` 头缺失或不匹配返回 401，使用常数时间比较，不泄露密钥长度时序。
- 密钥为空（默认）时门不启用，模拟器保持为开放的进程内测试替身。
- 与 §6 出口控制互补：出口白名单管"我们能连谁"，此令牌门管"模拟器能被谁连"。任何调用方（MCP Gateway 或未来直连客户端）必须携带该头，两端密钥由部署方对齐。

## 7. 幂等与重试

### 幂等规则

- 每个写Step在Plan确定后生成稳定幂等键。
- Tool执行前先写入执行意图和唯一约束。
- Tool成功后在同一业务流程中记录结果和外部操作标识。
- 恢复时优先查询已有记录或外部状态，不盲目重试。

### 重试规则

可以重试：连接重置、明确的暂时性5xx、受限429和可证明未执行的超时。

不能自动重试：鉴权失败、Schema错误、业务拒绝、参数冲突，以及执行结果未知且没有幂等保障的写操作。

重试使用指数退避、抖动、最大次数和Run deadline。

## 8. Worker恢复

恢复流程必须处理三种Step：

- 已成功：直接复用结果，禁止重复执行。
- 明确失败且可重试：根据预算重新执行。
- 状态未知：进入对账流程，查询外部操作结果或转人工。

Checkpoint恢复率和重复写次数必须通过故障注入测试测量。

## 9. 安全测试

至少覆盖：

- 用户Prompt Injection。
- 知识库RAG Poisoning。
- 未注册Tool和参数篡改。
- 跨租户文档和Run访问。
- 无Scope工具调用和越权审批。
- 回环、私网、DNS重绑定和重定向SSRF。
- 密钥在Prompt、日志和输出中的泄露。
- 重放审批、重复写和幂等冲突。
- 超大请求、超大Tool结果和拒绝服务。

报告攻击拦截率、误报率、漏报案例和每类攻击的测试数量。
