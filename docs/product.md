# 产品说明：ERP Agent Copilot V6

> 最终交付文档。详细设计见 `docs/01-product-and-scenarios.md` 与 `docs/03-agent-runtime.md`。

## 1. 项目定位

ERP Agent Copilot 面向需要跨库存、物流供应商和订单系统办理业务的企业用户。它不是普通问答机器人，而是一个**受状态机、权限策略、业务规则和审计约束的 ERP Agent Runtime**：把自然语言业务需求编译为可解释的 Tool DAG，自动完成跨系统查询、决策和提交，并保证写操作经过审批、执行可恢复、结果可验证。

### 一句话价值

将自然语言 ERP 业务需求编译为**可解释、可审批、可恢复**的跨系统工具调用 DAG。

## 2. 目标用户

| 用户 | 诉求 |
|------|------|
| 业务人员 | 用自然语言查询库存、物流和订单状态 |
| 订单运营人员 | 快速完成跨系统下单和订单状态维护 |
| 平台管理员 | 管理 Tool、Scope、知识库和租户策略 |
| 评测与安全人员 | 执行回归测试并分析失败、越权、注入事件 |

## 3. 产品目标（已实现能力）

- **工具注册与执行**：OpenAPI 3.x 导入、Tool/ToolVersion/Parameter 版本化、风险分级、MCP Gateway 持久连接与统一 `ToolResult`/`ToolError`。
- **知识检索**：L1 Rules（意图→规则确定性匹配）+ L2 RAG（pgvector + PostgreSQL FTS 混合检索 + Rerank），带引用与无依据拒答。
- **多步编排**：强类型 `AgentState` + LangGraph 状态机、Plan DAG 校验、只读步骤并行、写步骤串行。
- **安全与审批**：RBAC + Tool Scope、`policy_check` 门控、写操作人工审批、SSRF 出口控制、Prompt Injection 检测、输出 Redaction。
- **恢复与一致性**：Checkpoint 持久化、幂等键 at-most-once、指数退避重试、Worker 崩溃后对账恢复。
- **评测与可观测性**：175 条离线 Eval、Record/Replay 确定性回归、OpenTelemetry Trace、Prometheus 指标。

## 4. 非目标（范围控制）

- 不从零训练通用大模型。
- 不把有调用次数限制的真实 ERP 系统作为日常开发和评测依赖（使用本地 ERP Simulator）。
- 不创建多个可自由对话、行为不可控的 Agent 角色。
- 不拆分十几个缺少独立扩缩容需求的微服务（首版仅 API / Worker / MCP Gateway / ERP Simulator 四个进程）。
- 不在没有基线评测时进行 Embedding / Reranker 微调。
- 不把实时库存、价格、供应商和订单状态保存为向量知识库中的"当前事实"。

## 5. 演示场景

### 场景 A：跨系统订单创建

用户请求：`当前库存量充足的话，请帮我下一个发往上海的20KG苹果订单，并选择合适的物流供应商。`

期望行为：识别产品/数量/目的地/下单意图 → 查库存验证 → 查上海供应商并比较 → 组装订单参数 → Schema 校验 + 权限检查 + 用户确认 → 创建订单返回订单号与供应商。

验收标准：库存不足不创建订单并说明缺口；供应商候选必须来自 Tool 结果（禁止模型编造）；创建前展示摘要；同幂等键重复提交不产生重复订单。

### 场景 B：业务写操作与审批

用户请求：`将订单123的状态更新为"运输中"；如果缺少必要信息，先告诉我需要确认什么。`

期望行为：识别写意图与订单 ID → 校验状态转换合法性 → 标记为 WRITE → Run 暂停于 `WAITING_APPROVAL` → 审批通过后用幂等键执行 → 回查确认。

验收标准：未审批时写 Tool 调用次数必须为 0；审批人须具备正确租户/Scope/审批权限；重复提交、Worker 重启、消息重投不造成重复更新。

### 场景 C：异常、安全与任务恢复

演示内容：注入/越权请求被拦截并记录安全事件；危险 URL 被 SSRF 拦截；ERP 接口超时或返回瞬时错误；Worker 在部分 Step 完成后被终止。

验收标准：业务文档内容始终作为数据，不能覆盖系统策略与审批；SSRF 在发出请求前拦截危险地址；恢复后跳过已成功的写 Step；状态未知的写 Step 先对账；所有拦截/恢复/降级写入安全事件或 Run 事件。

## 6. V5 → V6 升级边界

| V5 能力 | V6 处理方式 |
|---|---|
| OpenAPI 工具导入 | 保留思想，重写为 OpenAPI 3.x 校验、版本化、风险分级 |
| Milvus 向量检索 + Rerank | 保留两阶段思想，重写为可评测的混合检索接口 |
| 工具选择 | 保留候选过滤思想，改确定性过滤 + 指标驱动 |
| 参数提取与缺参补全 | 增加 JSON Schema、来源追踪、冲突检测 |
| MCP | 保留协议，重做持久连接、健康检查和统一错误契约 |
| Flask + 线程池任务 | 不复用，改为 FastAPI + Celery + Redis + 持久 Run 状态 |
| MongoDB 任务状态 | 不复用，改为 PostgreSQL 事件 + Checkpoint |
| 简单注入判断 | 作为历史基线，重做五层安全策略 |

## 7. 10 分钟演示顺序

1. 1 分钟：人工跨系统下单痛点与 V5 局限。
2. 3 分钟：库存查询、供应商选择、订单创建。
3. 2 分钟：订单状态更新的审批暂停与确认。
4. 2 分钟：缺参、库存不足、注入或 SSRF 拦截。
5. 1 分钟：订单写超时后的对账恢复。
6. 1 分钟：评测报告与 Trace。
